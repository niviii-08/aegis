# audio/training - Audio Dataset and Training Pipeline

This module provides PyTorch datasets for audio deepfake detection training and evaluation.

## Overview

The audio training pipeline reads preprocessed features from split manifests (generated by `audio.splits`) and provides batched tensors ready for model training.

**Key features:**
- Speaker-isolated splits (no speaker leakage)
- Two feature modes: mel-spectrogram and wav2vec2
- Automatic augmentation (SpecAugment) during training
- Time-domain cropping (random for train, center for eval)
- Class balance measurement for weighted sampling

## Modules

### `dataset.py`

Main dataset module providing `AudioDataset` class.

**Features:**
- Reads from split CSVs + preprocessing metadata
- Supports two feature modes:
  - `mel_spectrogram`: [1, n_mels, T] tensors for CNN models
  - `wav2vec2`: [T, D] embeddings for transformer models
- Automatic augmentation based on `is_training` flag
- Configurable via dataclass configs

**Key Classes:**
- `AudioDataset`: Main PyTorch Dataset class
- `AudioSampleRecord`: Sample metadata container
- `MelSpectrogramConfig`: Configuration for mel features
- `Wav2Vec2Config`: Configuration for wav2vec2 features

**Key Functions:**
- `resolve_samples()`: Joins split CSV with preprocessing metadata
- `measure_class_balance()`: Computes class distribution
- `sanity_check()`: Validates dataset and prints diagnostics

## Feature Modes

### Mel-Spectrogram Mode

**Input:** `.npy` files with shape `[n_mels, T]` (e.g., [128, variable])

**Processing:**
1. **Time crop/pad** to fixed length (default: 600 frames = 6 seconds):
   - Training: Random crop from longer clips
   - Eval: Center crop from longer clips
   - Pad shorter clips with zeros

2. **SpecAugment** (training only):
   - Frequency masking: mask random frequency bands
   - Time masking: mask random time segments
   - Configurable via `MelSpectrogramConfig`

**Output:** `[1, n_mels, T]` tensor (channel-first for CNN)

**Configuration:**
```python
from audio.training.dataset import MelSpectrogramConfig

mel_config = MelSpectrogramConfig(
    n_mels=128,                      # Number of mel bands
    target_length_frames=600,        # 6 seconds at 10ms hop
    apply_spec_augment=True,         # Enable SpecAugment
    freq_mask_param=15,              # Frequency mask width
    time_mask_param=35,              # Time mask width
    num_freq_masks=2,                # Number of frequency masks
    num_time_masks=2,                # Number of time masks
    crop_mode="random",              # "random" or "center"
)
```

### Wav2Vec2 Mode

**Input:** `.npy` files with shape `[T, D]` (e.g., [variable, 768])

**Processing:**
1. **Pad or truncate** to fixed sequence length (default: 600):
   - Truncate: Take first N frames
   - Pad: Append zeros to reach target length

2. **No augmentation** (wav2vec2 embeddings are already robust)

**Output:** `[T, D]` tensor (sequence-first for transformer)

**Configuration:**
```python
from audio.training.dataset import Wav2Vec2Config

wav2vec2_config = Wav2Vec2Config(
    target_sequence_length=600,      # Fixed sequence length for batching
    pad_value=0.0,                   # Padding value
)
```

## Usage

### Basic Dataset Creation

```python
from pathlib import Path
from audio.training.dataset import (
    resolve_samples,
    AudioDataset,
    MelSpectrogramConfig,
)

# Paths
project_root = Path("/path/to/AEGIS")
split_csv = project_root / "data/processed/audio/splits/train.csv"
metadata_path = project_root / "reports/audio/preprocessing_metadata_mel_spectrogram.csv"

# Resolve samples (join split CSV with preprocessing metadata)
samples = resolve_samples(
    split_csv,
    metadata_path,
    project_root,
    preprocessing_version="v1",
    feature_mode="mel_spectrogram",
)

print(f"Resolved {len(samples)} samples")

# Create dataset (training mode)
mel_config = MelSpectrogramConfig(
    apply_spec_augment=True,
    crop_mode="random",
)

dataset = AudioDataset(
    samples,
    feature_mode="mel_spectrogram",
    mel_config=mel_config,
    is_training=True,
)

print(f"Dataset length: {len(dataset)}")

# Get a sample
features, label = dataset[0]
print(f"Feature shape: {features.shape}")  # [1, 128, 600]
print(f"Label: {label.item()}")            # 0 or 1
```

### Training vs Evaluation

```python
# Training dataset (with augmentation)
train_dataset = AudioDataset(
    train_samples,
    feature_mode="mel_spectrogram",
    mel_config=MelSpectrogramConfig(apply_spec_augment=True, crop_mode="random"),
    is_training=True,  # Enables random crop + SpecAugment
)

# Evaluation dataset (no augmentation)
val_dataset = AudioDataset(
    val_samples,
    feature_mode="mel_spectrogram",
    mel_config=MelSpectrogramConfig(apply_spec_augment=False, crop_mode="center"),
    is_training=False,  # Center crop, no augmentation
)
```


### Class Balance and Weighted Sampling

```python
from audio.training.dataset import measure_class_balance
from torch.utils.data import WeightedRandomSampler

# Measure class balance
balance = measure_class_balance(samples)
print(f"Real: {balance['real_fraction']:.1%}")
print(f"Fake: {balance['fake_fraction']:.1%}")
print(f"Minority: {balance['minority_fraction']:.1%}")

# Weighted sampling (if imbalanced)
if balance['minority_fraction'] < 0.4:
    # Compute sample weights
    class_counts = [balance['real_count'], balance['fake_count']]
    class_weights = [1.0 / count for count in class_counts]
    sample_weights = [class_weights[sample.label] for sample in samples]
    
    # Create weighted sampler
    sampler = WeightedRandomSampler(
        weights=sample_weights,
        num_samples=len(samples),
        replacement=True,
    )
    
    train_loader = DataLoader(
        train_dataset,
        batch_size=32,
        sampler=sampler,  # Use weighted sampler instead of shuffle
        num_workers=4,
    )
```

## SpecAugment Details

SpecAugment applies random masking to mel-spectrograms during training:

**Frequency Masking:**
- Randomly selects `num_freq_masks` frequency bands
- Each band has width ≤ `freq_mask_param` bins
- Sets selected frequencies to 0

**Time Masking:**
- Randomly selects `num_time_masks` time segments
- Each segment has width ≤ `time_mask_param` frames
- Sets selected timesteps to 0

**Benefits:**
- Prevents overfitting to specific frequencies
- Forces model to learn robust temporal patterns
- Standard augmentation for speech/audio tasks

**Configuration:**
```python
MelSpectrogramConfig(
    apply_spec_augment=True,
    freq_mask_param=15,    # Mask up to 15 frequency bins
    time_mask_param=35,    # Mask up to 35 time frames
    num_freq_masks=2,      # Apply 2 frequency masks
    num_time_masks=2,      # Apply 2 time masks
)
```

## Speaker Isolation

**CRITICAL:** All clips from the same `speaker_id` are in the same split.

This is enforced by `audio.splits.generator_split` and maintained by `AudioDataset`:

```python
# Load train split
train_samples = resolve_samples(...)
train_speakers = {s.speaker_id for s in train_samples}

# Load test split
test_samples = resolve_samples(...)
test_speakers = {s.speaker_id for s in test_samples}

# Verify no overlap
assert len(train_speakers & test_speakers) == 0
```

**Why this matters:**
- Prevents speaker memorization (model learning speaker identity instead of forgery)
- Tests true generalization to unseen speakers
- Standard practice in speaker recognition and anti-spoofing

- Both use `resolve_samples()` to join manifests
- Both provide `measure_class_balance()`
- Both support training vs eval modes
- Both integrate with PyTorch DataLoader

## Troubleshooting

| Issue | Cause | Solution |
|-------|-------|----------|
| "Split manifest not found" | Split CSVs not generated | Run `python -m audio.splits.generator_split` |
| "Preprocessing metadata not found" | Features not extracted | Run `python -m audio.preprocessing.preprocess` |
| "No samples resolved" | Preprocessing incomplete or version mismatch | Check preprocessing status and version |
| "Expected 2D mel, got 3D" | Wrong .npy file loaded | Check feature_mode matches preprocessing mode |
| Shape mismatch in DataLoader | Variable sequence lengths | Check target_length configuration |

## Design Rationale

### Why Two Feature Modes?

**Mel-spectrogram:**
- Traditional audio representation
- Works well with CNN architectures
- Faster training (smaller features)
- More interpretable (time-frequency heatmap)

**Wav2vec2:**
- Pre-trained self-supervised embeddings
- Captures semantic audio information
- Better for transformer architectures
- Transfer learning from large corpora

### Why SpecAugment?

Standard augmentation for speech/audio:
- Prevents overfitting to specific frequencies
- Forces model to learn robust patterns
- Improves generalization to unseen conditions
- Widely adopted in ASR and audio classification

### Why Fixed-Length Sequences?

**Benefits:**
- Enables efficient batching
- Simplifies model architecture
- Consistent memory usage
- Faster training

**Tradeoffs:**
- Clips are cropped (lose some context) or padded (wasted compute)
- Solution: Choose target length based on dataset statistics

## Future Enhancements

- Mixup augmentation (blend two samples)
- Variable-length batching with padding
- Multi-clip aggregation for longer utterances
- Configurable augmentation pipeline
- On-the-fly feature extraction (instead of pre-computed)
